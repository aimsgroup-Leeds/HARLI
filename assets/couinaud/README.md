# HARLI Couinaud model

The interactive model in “Explore the eight Couinaud segments” is extracted
from a real case in Xukun Zhang and colleagues’ published Couinaud annotations.
It is a prepared anatomical asset, not a prediction made by HARLI or a mesh
generated by Vis2Reg. No synthetic vessels, tumours or segment boundaries are
added.

## Labels and scientific scope

The source contains background `0` and eight nonzero labels. Display names
currently follow the ordinal convention `1 → I`, `2 → II`, `3 → III`,
`4 → IV`, `5 → V`, `6 → VI`, `7 → VII`, `8 → VIII`. This mapping is
provisional: an explicit label dictionary was not found in the pinned source,
and it can be updated if the annotation author supplies a correction.

Segment IV is one source label. There is no separately annotated IVa/IVb
boundary in this case, so the viewer does not fabricate one. The complete
liver surface is the union of the eight labels. The repository includes only
surfaces prepared for browser display, not the original CT or annotation
volume. Display colours are presentation choices.

## Reproducible asset preparation

[`../../scripts/build_couinaud_model.py`](../../scripts/build_couinaud_model.py)
verifies the source checksum and the label values before producing
[`model.json`](model.json) and [`build-report.json`](build-report.json).
It requires Python with `numpy`, `scipy`, `nibabel`, `scikit-image`, `trimesh` and
`fast-simplification`:

```sh
python scripts/build_couinaud_model.py /path/to/3Dircadb-1.nii.gz
```

Each segment and the union surface are prepared separately from their source
binary masks. A three-voxel background border surrounds each cropped mask.
Gaussian scalar-field smoothing with `sigma=0.6 mm`, converted to each native
axis’s voxel spacing, reduces voxel stair steps before marching cubes at level
`0.5` and native-grid step size `1`. Coordinates are transformed with the full
NIfTI affine; voxel spacing and orientation are accounted for. All surfaces
then share a right-handed display transform with axes patient left, superior,
anterior.

Browser preparation applies eight Taubin smoothing iterations (`lambda=0.5`,
`nu=0.5`) and quadric decimation (`aggression=5`). Initial budgets are 7,000
triangles per segment and 14,000 for the union; the budget doubles when needed
to retain a watertight surface, falling back to the unsimplified surface if
necessary. All parts are centred and uniformly scaled together, and exported
coordinates are rounded to five decimal places. No artificial cutting planes
or inferred subdivisions are used.

The JSON retains the source grid, voxel spacing, affine, shared centre and
scale, source IDs and processing description. The build report records source
and display triangle counts, voxel counts, and watertightness for all nine
surfaces. Smoothing and simplification are for display and are not a new
segmentation or a clinical validation of the annotation.
